    [0.2.0] 2026-11-27¶

    Added¶

    • Added the proxy reference to the virtual coefficient lab: ScatteringSample.as_drawn(mesh, reference=proxy) takes the simplified mesh the room model will carry the lab's s on, so that s measures the share of the detailed object's reflection that the proxy does not reproduce; sample.reference_kind is "flat" or "proxy", and a proxy result is flagged non-ISO.
    • Added the diffusion coefficient to the lab: diffusion_coefficient (ISO 17497-2 eq. 6) and normalised_diffusion, and ScatteringResult.d_angle, d_bands and d_octaves (d_n per source, one-third-octave band and octave, with the same random-incidence weights as s), returned by every method.
    • Added method="geometric" to measure_scattering: a fast heuristic preview (seconds, against minutes for Kirchhoff). n_rays specular rays per source direction reflect off the rigid sample and reference, mounted in a rigid baffle at z = 0, and are binned on the receiver hemisphere; s is the geometric s_max times the depth curve 1 - exp(-(2 pi f h / c)^2), with no phase and no diffraction. Its accuracy against Kirchhoff is recorded in the module docstring of compas_acoustics.lab.geometric. It needs trimesh (and embreex for speed) on Python >= 3.11, which the lab extra now installs.
    • Added compas_acoustics.lab.raycast.RayCaster, the first-hit ray caster (trimesh with the Embree backend) behind the geometric method.
    • The geometric method warns when an object stands a mean height above the mounting plane of more than twice the spread of its relief, which is what a closed mesh on a backing thicker than baseplate looks like: the backing then sets the depth h. GeometricResponse gained height_mean and height_spread. If the backing sits flush on the wall, pass its thickness as baseplate to as_drawn.
    • Added the Grasshopper virtual coefficient lab, three components in a new "Lab" subcategory: Scattering Sample (a mesh, Brep, surface or SubD as a relief to measure, as_drawn or a repeated disc), Scattering Lab (the scattering and diffusion coefficients of a sample by the geometric, kirchhoff or bem method) and Polar Preview (the reflected level of one preview source and octave as a coloured balloon at centre). Scattering Lab's scattering output, the 7 octaves of a material, wires into Construct Material. The geometric method runs when its inputs change; Kirchhoff and BEM take minutes to hours and run only on the Run button. The lab measures an object that lies on the World XY plane facing +Z; Scattering Sample has an optional plane input (the frame argument of make_scattering_sample) for an object that lies elsewhere, and an object whose footprint on XY has no area is a readable error. Scattering Lab keeps its run (or its result) when Scattering Sample is solved again with the same geometry, and says when its outputs are the last run's because the inputs changed.
    • Added the compas_pb messages ArrayData, ScatteringSampleData and ScatteringResultData, and the worker functions make_scattering_sample(mesh, mode, diameter, reference, baseplate, symmetry, period, name, frame), run_scattering_lab(sample, method, preset, band_range, settings), and polar_balloon(result, preview, octave, body, radius, floor_db).
    • run_scattering_lab returns the heuristic note of the geometric method (that s is modelled from the geometry, not computed) as notes and no longer in warnings, and the Scattering Lab component shows it as a Remark instead of a warning; measure_scattering still warns, and a kirchhoff or bem run has no notes.
    • The Polar Preview balloon (polar_balloon) keeps a 3 % minimum radius, so that a sparse geometric result, most of whose cells are empty, still gives a valid mesh instead of one collapsed to the centre.
    • Added the Save RIR button to Auralise and the worker function save_impulse_responses: the impulse responses of the chosen pairs as WAV files, named as Save auralisation names its signals (<name>_mic_<r>_<s>.wav), at the level the body chooses, each with its JSON metadata. ImpulseResponse.to_wav takes a gain on the raw response and records its inverse as the factor from_wav reads back. Auralise's Save button is now Save auralisation.
    • Added a flamenco guitar excerpt (guitar.wav, TH Koeln Audio Group, CC BY-SA 3.0) and a castanets rhythm (castanets.wav, Matthias Frank, IEM Graz, CC0) to anechoic_soundfiles_library, with their sources and licences in its README.
    • Added the worker function room_measures(scene): the volume of a closed room (else None) and the area exposed to the air, as the simulation methods take them, for the Acoustic Scene message.

    Changed¶

    • The Grasshopper plugin is released with the library: its version is the library's, and it requires that release of compas_acoustics (>=X.Y.Z up to the next breaking release). bump-my-version updates both versions in the .csproj, and release.yml publishes the plugin to Yak after the library is on PyPI. publish_yak can still be run by hand.
    • Changed Plot 2D to show a one-sentence description of the chosen parameter right of the Select parameter dropdown (dimmed while the dropdown rests): what the parameter is and its standard, from one table beside PlotSelection.Names.
    • Changed Visualise Energy Map to compute the map when its Run button is pressed (or its new run input is true), not on every change of its inputs: the map takes seconds, and on the one worker it slowed the components that run on every change of the scene, Simulate Mono among them. Until a press the last map stays drawn; changing the band or the range redraws it without a run.
    • Changed Simulate Mono to simulate when its Run button is pressed (or its new run input, its last, is true), as Simulate Binaural and Simulate Ambisonics do, not on every change of its inputs. Until the first press it outputs nothing and says "press Run" (a hybrid with Tail Reference waits for its reference meanwhile). After a run it passes its responses on until the next run, a change of a source's sound included, and says when the settings differ from the run's; Cancel stops a run.
    • Removed the energy_thres input of Simulate Mono: it runs with the method's 1e-7, pyroomacoustics' own (Mono(energy_thres=) stays in Python). A definition saved with another value reads with its inputs in place and remarks that the responses now use 1e-7 until it is saved again.
    • Changed the Grasshopper components to take the descriptions of the installed plugin when a definition is opened: Grasshopper restored those the file was saved with, so a definition from an earlier release showed its tooltips.
    • Changed Simulate Mono, Simulate Binaural and Simulate Ambisonics to take the methods' own seed, 42, when the seed input is left as it is, in place of a new random seed on every run: the components give what Mono(), Binaural() and Ambisonics() give in Python. The seed port shows 42, and the message names the seed the run used.
    • Changed Simulate Mono, Simulate Binaural and Simulate Ambisonics to keep their responses when the model changes, until Run is pressed again, where they output nothing: the message says "model changed, rerun the simulation" and a warning colours the body; a change of the settings says "settings changed, rerun the simulation", for Simulate Binaural and Simulate Ambisonics now every setting and a reference simulated again (they compared only the tail, the orders and diffraction). A recompute that only draws new guids (receivers, objects, materials, sources) leaves the model as it was: the responses hold, carrying the current guids. While their responses hold the message says how many they simulated (simulated 4 responses), no longer the sampling rate (48 kHz, 4 responses). While they run it says simulating and, per response, simulating 2/4: the worker's progress stage of Mono (was image sources or ray tracing, then responses) and of the hybrids' rendering (was rendering). Simulate Binaural and Simulate Ambisonics refuse a reference that Simulate Mono kept from an earlier model, with a warning, and an error on Run: "The reference is from an earlier model: rerun Simulate Mono first."
    • Changed Simulate Mono's body to that of Simulate Binaural and Simulate Ambisonics: the ISM order slider. Ray tracing is an input (default on), no longer a toggle; the Air toggle and its absorb_air input are gone, and Simulate Mono always includes air absorption, as the hybrid components do (Mono(air_absorption=) stays in Python). A definition saved with the former body reads with its inputs in place, shows Ray tracing as an input with its saved value, and, if saved with Air off, remarks that the responses now include air absorption until it is saved again.
    • Changed the ISM order of Simulate Mono, Simulate Binaural and Simulate Ambisonics to a slider of stops, one per order from 0 to 10, labelled under the track, as Polar Preview's octave slider; it shows 3, the methods' default, until moved.
    • Changed the order of Visualise Rays to a slider of stops, one per order from 1 to the traced max_order and All (the default, the empty input: every traced order); beyond 12 orders only every k-th stop is labelled. The stops follow max_order.
    • Changed Visualise Rays to play at a chosen speed and time: a time slider (ms; it scrubs and follows the playback) and a Speed dropdown (0.25x to 4x, a factor of the whole field in 10 s) beside Play and Rewind, with the inputs time and speed. The rays are drawn from Play or a time on. Its max_order and seed inputs hide with the control inputs on a new component ("Show control inputs" shows them). A definition saved before keeps max_order and seed where they were and reads time and speed hidden when it saved its control inputs hidden.
    • Changed Visualise Billiard to trace its own rays from a scene and play them as balls, as Visualise Rays plays its rays: the inputs of Visualise Rays (scene, source_idx, n_balls in place of n_rays, max_order, direction, angle, order, time, speed) without scattering, and the same body (source, order, time, Speed, Play and Rewind). A definition saved with the former Visualise Billiard reads with the inputs of a new one: connect a scene.
    • Changed the step sliders (the ISM order, the Ambisonic order, Polar Preview's octave, Visualise Rays' order) to span the width of the body: the track's ends stand half the end label, the knob's radius and a small margin from its edges.
    • Changed Simulate Ambisonics' SH order dropdown to the Ambisonic order, a slider of stops from 1 to 7 as the ISM order's, still a choice of the component without an input; a definition keeps the order it was saved with.
    • Changed Source's Sound file... button to the Anechoic sound dropdown of Auralise, on a sound input after spl (was sound_file, before spl): a bundled recording (Female speech, Male speech, Viola, Guitar or Castanets) or a file chosen with Load..., none on a new Source. Auralise auralises the pairs of a Source with its sound in place of its own. A definition saved with sound_file, or before Source had a sound, reads without it, sound empty and hidden.
    • Changed Polar Preview to centre the balloon, when centre is not given, on the result's sample as Scattering Sample draws it: the centroid of its footprint in x and y and its top in z, where it was the origin. run_scattering_lab records the centre in the result's generation (sample_centre), and polar_balloon returns it as centre (None for a result without it). A wired centre still wins.
    • Changed the geometric method of the lab to report progress and to stop at the next source when cancelled.
    • Changed the worker to install compas_acoustics[lab] (trimesh, embreex, mesh2scattering): reinstall the worker to use the lab. NumCalc, which bem needs, is a separate setup step. The Grasshopper Install Worker component installs the extra too (it installed compas_acoustics without it, so the geometric method and bem failed in a worker it had set up).
    • Changed the messages of the lab (ScatteringSample, measure_scattering, the Kirchhoff and BEM solvers, the ray caster, and the Scattering Sample and Scattering Lab components) to one short sentence each, about 90 characters, that names what is wrong and the input that fixes it. The octaves filled from a simulated one are one warning, not one each; a run of measure_scattering with bem warns once about unconverged steps (the result's warning, with its octaves, in place of the solver's) and once about a large mesh.
    • Changed Scattering Sample and Scattering Lab to leave out an input the chosen mode or method does not use (reference in disc mode; n_rays and max_bounces with kirchhoff or bem; cache_dir with geometric or kirchhoff) and to name it in a Remark, where they warned and did not run. Such an input no longer makes another run.
    • Changed which messages of the lab components are warnings. A warning now means the outputs may be wrong or are not those of the inputs; a fact about the run is a Remark: the octaves not simulated, bands beyond ISO 17497, the geometric heuristic, Kirchhoff falling back to one process, and on Scattering Sample the ISO 17497-1 depth limit and a proxy reference. run_scattering_lab returns these as notes, leaves out the sample's own warnings (Scattering Sample shows them, so Scattering Lab no longer repeats them) and leaves out how long a run takes and the large-mesh and many-receiver notices, which reach the component only after the run.
    • Changed Scattering Lab's Run button to say what pressing it does while kirchhoff or bem waits for it: "Press Run to start", or "Press Run to update" when the outputs are the last run's. It replaces the Remark "Press Run…" and the "press Run" text under the component.
    • Changed the dropdowns and switches of the Grasshopper components to show an option without its underscores ("as drawn", "ray tracing"); the value the worker gets and a definition saves is unchanged.
    • Removed the fine source preset (864 directions, Heimes and Vorländer's grid) of SourceGrid.preset and measure_scattering, and from Scattering Lab: survey (13) and standard (97) remain.
    • Changed a ScatteringResult to hold the polar levels of every source direction (polar_source_indices lists them all), not only the 13 nearest ISO 17497-2 Table 1, so that Polar Preview offers each direction measured. compas_acoustics.lab.scattering.preview_sources is removed. A standard result of a 1.4 m sample holds about 20 MB of levels (about 60 MB to 8000 Hz).
    • Changed Polar Preview's incidence selection from a dropdown to two dials side by side: a section through the sample for the colatitude θ and a plan for the azimuth φ, with a tick for each direction the result has and an arrow from the chosen one to the sample. Picking a colatitude keeps the azimuth (or the nearest one the ring has); at the normal the azimuth dial is grey. The dials set the same preview input, so saved definitions keep their direction, and a wired preview greys them. The component is at least 176 px wide to fit them. Its octave is a horizontal slider with a stop per octave, 125 Hz to 8 kHz: an octave the result did not simulate (8000 Hz for the ISO range) is grey and the knob does not stop there, and a definition saved at such an octave shows and draws the nearest simulated one. The strip under the component is empty: the dials and the slider show the choice.
    • Changed the strips under Scattering Sample and Scattering Lab to leave out what their dropdowns show: the sample's reads its diameter (d 1.41 m), the result's its range of scattering coefficients (s 0.06–0.94).
    • Changed Polar Preview to name its result by its guid: the worker holds the results it made or was sent (polar_balloon takes a result or the guid of a held one, up to 1 GB of levels, the least recently used let go first), so a change of the direction, octave or body no longer sends the result again. A worker that does not hold it (after a restart) answers with NOT_HELD, and the result is sent once.
    • Changed the preset of Scattering Lab to default to survey (13 source directions), and removed its "Default" option, which took the method's own (standard). measure_scattering keeps standard. A definition saved with "Default" now runs survey, as its dropdown shows.
    • Fixed the Preview switch of Polar Preview, which did not hide the balloon: it shared its name with the preview input (the source index), so a click set that input instead.
    • Removed the name input of Scattering Sample: the name labelled the sample and its result in a panel and nothing else. make_scattering_sample and ScatteringSample keep their name.
    • Added max_bounces to Scattering Lab: the reflections a ray of the geometric method may make before it counts as lost (default 20), the remedy its lost-rays warning names.
    • Changed the default method of measure_scattering to "geometric" (it was "kirchhoff"); pass method="kirchhoff" for the previous behaviour, which needs neither trimesh nor Python >= 3.11. Every method now defaults to the "standard" source preset.
    • Changed the default ray count of Mono from 20000 to room.raytracing.default_rays: the rays at which a direction's energy over one slot of the hybrid's late envelope has a standard deviation of 1 dB on its 96-line grid (Vorlaender 2020, Eq. 11.20), from the room's volume, at least 20000 (MIN_RAYS, formerly the 50000 floor on pyroomacoustics' heuristic, which n_rays=None no longer gives). Binaural and Ambisonics trace their own reference and directional histograms with the same rule, now also at least 20000, so a Mono reference traces what they trace themselves; their responses move in rooms below about 1050 m3. They take n_rays to set those rays, refused when they trace none. In Grasshopper, Simulate Binaural and Simulate Ambisonics have an n_rays input, and Simulate Mono's n_rays port is empty by default (a definition saved with its former 20000 reads empty).
    • Changed the default duration of Mono with ray tracing, and of the reference Binaural and Ambisonics trace themselves, to trace again at 1.5 times the longest T30 read while the responses end before 2/3 of it, up to 12 s, in place of warning: the Eyring-based length cuts the decay of a room whose absorption sits on a few surfaces. A given Mono duration is kept and still warns.
    • Changed late_envelope of Binaural and Ambisonics from on/off to "omni", "directional" or False, and the default with a reference or a ray-tracing tail to "omni": the late field takes the reference's level per band, and its delay lines keep the network's spread over directions, weighted by directional_absorption. "directional" is the former True, with every line given its direction's share of the ray-traced energy per band; it traces the directional histograms, which "omni" does not (generation["histogram_rays"] is then None). A reference the method traces itself takes the ray count of the directions' rule (hybrid.envelope.histogram_rays, a direction's energy to 1 dB) in both modes, so both shape the late field to the same reference. late_envelope=True raises, naming the three values. The Grasshopper components' Late envelope toggle is a dropdown (omni, the default, directional, off), and a definition saved with the toggle keeps its choice (on as directional, off as off); with an Eyring or Sabine tail, which the methods refuse a mode with, the dropdown rests and the late envelope is sent off.
    • Changed Binaural and Ambisonics with a given Mono reference at their image_source_order to take the early field's images from the reference's own image source search (room.reflections.damping_as_searched), as a ray-tracing tail does, in place of a second search of the room; the responses are bit-identical.
    • Changed Binaural and Ambisonics to render the source-receiver pairs on threads, as many as fit in about 4 GB at a pair's peak memory; the responses are bit-identical and in the same order.
    • Changed the hybrid's feedback delay network to filter its lines with the kernel of scipy.signal.sosfilt called directly, without that function's checks of its arguments in every block; the responses are bit-identical, the network about twice as fast.
    • Changed Analyser.plot to label its axes as the Grasshopper plots do, from one table that the worker also serves ("Value (%)" for D50, "Modulation transfer index (0-1)" for the bands of STI).
    • Changed the error for a wrong number of band values of Source.spl and the AcousticMaterial coefficients to one wording.
    • Changed the worker to check the token of a call before registering it, so an unauthorised call leaves a running call with the same id alone; a POST to an unknown route without the token answers 401.
    • Changed room.diffuse.predicted_rt to use pyrato's Sabine and Eyring (pyrato.parametric) where they exist (pyrato >= 1.0, Python >= 3.11), and its own lines in pyrato's order of operations where they do not; on Python < 3.11 a mean absorption at or below 1e-10 now gives a large finite Sabine time, as pyrato does, instead of inf.
    • Changed hybrid.synthesis.prepare to take diffraction as None, "udfa" or "btms" and to require duration_s; Binaural and Ambisonics still take diffraction=True and default to 1.5 times each pair's longest target reverberation time.
    • Changed the allpass cascade of the hybrid's surface scattering (scattering=True) to run block by block, about 28 times faster; the responses agree with the former filter to about 1e-14 of their peak.
    • Changed BTMS diffraction to compute the edge coordinates of the second order once per segment, not once per segment pair, and the diffracting edges once per room geometry: about 1.4 times faster, the responses bit-identical. The edge warnings come once per simulation, not once per source-receiver pair.
    • Changed RoomGeometry to compute its face areas, normals, exposed faces and volume once; the responses are bit-identical.
    • Changed names in the hybrid engine: hybrid.late.render is hybrid.late.run_network; hybrid.diffraction.toolbox_frame and toolbox_cyl are edge_frame and edge_cyl; the Pair argument of the engine's functions and HybridCore.spec are pair; hybrid.diffraction.pair_valid takes the two angles; the first argument of room.pra.directivity_to_pra is directivity.
    • Changed the worker's error for an unknown time_scale to name its options once.
    • Changed the Grasshopper Simulate Mono, Simulate Binaural and Simulate Ambisonics messages to one format (48 kHz, ..., SH order N for the hybrid's spherical harmonic order); a message longer than the strip is cut there, the full text in the tooltip. Corrected component texts: Play reads Pause while playing, Install Worker installs a version range, the hybrid seed also seeds the rays the method traces. Material Library bars use the picker's colours.
    • Changed the hybrid's feedback delay network to fall back to pyFDN's SOSBank when scipy's private sosfilt kernel cannot be imported; the output is the same.
    • Changed Analyser to start every parameter's windows, LF and LFC included, at one onset: pyfar.dsp.find_impulse_response_start on channel 0 (the 20 dB criterion of ISO 3382-1). It replaces the package's own start search and, for LF and LFC, the geometric direct-sound sample; where the direct sound is weak or blocked the parameters move (on the test rooms C50 up to 0.7 dB, D50 up to 2.3 %, DRR up to 11 dB at 125 Hz, Ts up to 3 ms, LF up to 0.06).
    • Changed Analyser.clarity_definition to give C50, C80 and D50 as NaN when the early or late part has no energy, as DRR does, without the 1e-12 offset; print_table and export_csv show the stored values, not values rounded to 2 decimals.
    • Changed the BTMS first-order integrand and its quadrature to be written from the published line integral (Calamia and Svensson 2007, Eqs. (2)-(4)) and the standard adaptive Simpson rule with Richardson extrapolation; the responses are bit-identical.
    • Changed Simulate Mono, Simulate Binaural and Simulate Ambisonics to output irs, the impulse responses in scene order (receiver by receiver, the sources within each), in place of mono_ir_graph, binaural_ir_graph and ambisonic_ir_graph. Connect irs to Analyse Impulse Response, Auralise or the Audio Player directly; the reference of Simulate Binaural and Simulate Ambisonics takes the irs of Simulate Mono, and a reference that lacks a source-receiver pair of the scene is an error that names the pair. A definition saved with the former outputs opens with them named irs. Python's Scene.ir_graph is unchanged.
    • Removed the Normalize toggle of Simulate Mono, Simulate Binaural and Simulate Ambisonics: Grasshopper reads the raw level of the responses (the Audio Player's Normalize and Auralise's level choose the level of what is played or saved). A definition saved with the toggle reads without it.
    • Changed Analyse Impulse Response to take irs (the responses of Simulate, one or many) with a Source and a Receiver dropdown (source_idx and receiver_idx: All, or one by number and name; a wired list of integers chooses several). The n-th distinct source (receiver) among the connected responses, in the order they come, is source (receiver) n. parameters, time and frequency hold one branch per pair, path {receiver;source}, and the chart titles name the pair.
    • Changed Plot 2D to take a select dropdown, Select parameter, beside its data input (T30 until chosen, All, or one parameter by name, each with its title in the opened menu, as T30 (Reverberation Time); its width does not follow the charts'), as Deconstruct Parameter did, and to read its data as a tree: one chart per parameter over every branch. The time and frequency responses are charted whichever parameter is chosen; with only them connected the dropdown rests, dimmed, and keeps its choice.
    • Changed Auralise to take irs, the Source and Receiver dropdowns of Analyse Impulse Response and one sound: choose it on the Anechoic sound dropdown, a bundled recording (Female speech, Male speech, Viola, Guitar or Castanets; none is chosen on a new Auralise, which warns until one is) or a file chosen with its last entry, Load..., which the dropdown then lists by its name, or wire a File Path (a wired path wins). A definition saved with the former Anechoic sound button reads its file back as the loaded entry, chosen. signals holds one branch per chosen pair, path {receiver;source}. A pair whose Source has its own sound (the same Anechoic sound dropdown on Source) is auralised with it, the others with Auralise's sound; Auralise warns only when a chosen pair has neither. The level relative takes its gain from every connected pair convolved with its sound, not only the chosen ones, so a chosen pair keeps its level difference to the loudest connected one. The level is a dropdown (none, the default, relative or individual) in place of the three-button switch, whose default was relative: a definition saved with a level chosen keeps it, but one saved without choosing a level used to auralise at relative and now opens with none, the raw level, which may clip (the clip warning says so); choose relative to restore the former behaviour. Save auralisation and Save RIR write the chosen pairs as <name>_mic_<r>_<s>.wav, with r and s the receiver and source numbers.
    • Changed the Audio Player to take no Source: the responses it plays come from Simulate directly.
    • Changed Analyse Impulse Response to note a binaural or ambisonic response analysed on its first channel as a Remark, not a Warning: the worker's analysis returns that message in notes (analyser.CHANNEL_NOTE).
    • Changed the Audio Player to say why it cannot play a signal (more than two channels, or a playback error) only in its warning: the body keeps its header line.
    • Changed Analyse Impulse Response and Plot 2D in Grasshopper to no longer show LFC (the worker's analysis does not return it); Analyser still computes it.
    • Changed the Plot 2D Select parameter dropdown to list All and the parameters connected, in place of every parameter (no LF for a response that is not ambisonic); with nothing connected it lists every parameter. A parameter chosen or saved that is not in the connected data stays shown and gives a warning, which for LF says it needs an ambisonic response (Simulate Ambisonics).
    • Changed the worker functions of the plugin's interface: analysis(irs, ...), auralise(irs, sound, chosen, labels, ...) and save_impulse_responses(irs, chosen, labels, ...) take the responses and the chosen pairs; auralise takes a bundled recording by its name (female_speech, male_speech, viola, guitar, castanets) or a file's path, or None, and auralises each response with the sound_file of its source where that has one; make_source takes sound_file the same way, a bundled recording by its name or a file's path. A plugin and a worker of different builds do not work together: use Install Worker again after updating.
    • Changed Grasshopper's Simulate Binaural and Simulate Ambisonics to default Tail to Ray tracing and to drop the Auto option: they always send an explicit tail to the worker, and a connected reference needs Tail Reference (any other tail is an error before the worker is called). A definition saved with Auto reads as Reference when a reference is connected and as Ray tracing otherwise. The Python API is unchanged.
    • Changed the test suite to drop the tests whose assertions other tests already make (160 Python tests and 60 C# test cases), to merge tests that make the same call into one, and to drop the tests left from development: tests that only check that a removed component, input or argument is gone, tests that copy a constant or a formula of the code, and tests of code nothing calls any more; and to drop the tests of the BEM solver and NumCalc (tests/lab/test_bem.py, the BEM convergence and cache-directory cases of the scattering lab and its component, and the validation against the Zenodo 15673498 results). Each band keeps its total, 16 kHz included; a band's shares are held once its own rays have decayed 60 dB; a histogram on other bands is refused. Against exact image-source shoeboxes with direction- and frequency-dependent absorption the per-direction late level error falls from up to 10 dB to 0.2-1.2 dB per band. The shaping takes about five times as long (one share computation per band). The directional histograms trace as many rays as give a direction's energy over one smoothing window a standard deviation of 1 dB (hybrid.envelope.histogram_rays, after Vorlaender 2020, Eq. 11.20: proportional to the room volume and the number of lines); at Mono's 20000 the per-band late directions of a 2300 m3 open-plan office were mostly ray noise. That office takes 44147 rays, a 640 m3 office 12051, a 320 m3 room about 6000. The count is recorded as generation["histogram_rays"].

    • Changed the hybrid's ray-tracing tail to one image source search and one ray trace: its reference, Mono(ray_tracing=True), is traced with a copy of every receiver that sorts the same rays by direction, so the directional histograms are no second trace, and the reference's search gives the early field's images, whose damping without the specular factor, or the scattered parts of scattering=True, are read from it (room.reflections.damping_as_searched: every image's walls are traced back from a receiver and kept where the search's own mirroring, visibility test and float32 product give that image bit for bit, so the other build's product along them is its search's; where they leave that damping open, as with two images at one position whose products differ only in the other build, that room is searched).     Changed¶

    • Changed the worker's playback API: play(sound, normalize=True, gain_db=0.0, start=0.0) returns the duration; pause, resume, stop, playback_status and sound_samples are new.
    • Changed how the hybrid's early renderer and late envelope compute, not what: early.render_images and render_transfers accumulate the paths' spectra as matrix products over chunks of paths instead of one outer product per path, and envelope.octave_band_split applies pyfar's reconstructing bank as one FFT per channel and one inverse FFT per band (zero-padded past the filter length, the linear convolution pyfar computes) with the bank designed once per sampling rate. Responses are unchanged to rounding.
    • Changed Analyser.speech_transmission_index to reduce the modulation transfer function it already has with pyrato's _sti_calc (IEC 60268-16:2020 Annex A.2.1) instead of calling speech_transmission_index_indirect, which computes the same MTF again; without _sti_calc the indirect method is called.
    • Changed the ray tracer's defaults: energy_thres 1e-7 (pyroomacoustics' own), since libroom stops a ray on the product of its wall reflections while the receiver logs that energy over the squared distance; and duration 1.5 times the longest Eyring reverberation time within 0.5 to 12 s. The runs Binaural and Ambisonics make themselves, a ray-traced reference and the directional histogram, take the same default. A reference shorter than 2/3 of its reverberation time warns, since pyFDN's decay fit shrinks its range to what the response has. A ray-traced response that ends before 2/3 of its own longest T30 warns with the length to rerun with: a room whose absorption is concentrated on a few surfaces can decay far slower than Eyring predicts. A room whose Eyring prediction hits the 12 s cap also warns (raytracing.default_duration): its rays live for hundreds of reflections, usually from a material with no low-frequency absorption on a large surface.
    • Changed the JSON data type of every compas_acoustics class to compas_acoustics/<ClassName> (was compas_acoustics.<module>/<ClassName>), so that saved data no longer depends on the module a class lives in; the materials library is stored that way. Files saved before do not load.

In the binaural response each line is heard through its own HRIR. The methods take no num_delays or drive_gain: the count follows from sh_order (Ambisonics) or is 96 (Binaural), and the input gain sqrt(num_delays) offsets the output's 1 / sqrt(num_delays), so the late level does not depend on the count; hybrid.synthesis.prepare keeps both.     • Fixed the single-number values of C50, C80, D50 and Ts averaging 500, 1000 and 2000 Hz: they average 500 and 1000 Hz, as ISO 3382-1:2009 Table A.1 has it for G, EDT, C80, D50 and Ts (C50 follows D50), like EDT, T20 and T30 already did.
    • Fixed responses simulated in the worker (the hybrid in Rhino) always coming back as peak-normalized views: they keep the method's normalize. Their raw level was already kept.
    • Fixed the Grasshopper Material Library component forgetting its material when the file is reopened: the choice is kept in the component's nickname, which Grasshopper saves.
    • Fixed the Grasshopper Material Library component failing with No module named 'compas_acoustics': its script pinned an empty Rhino script environment, compas_acoustics_rhino, instead of the one the installer fills.
    • Fixed the worker setup from the Grasshopper installer failing at its last check: the worker's Python 3.12 inherited the PYTHONPATH of Rhino's 3.9 packages and could not import numpy.
    • Fixed a simulation failing on a Source whose sound_file is not a RIFF WAV (an AIFF or FLAC file; the library's bassoon.wav is an AIFF): the file is read with soundfile.
    • Fixed the hybrid engine counting an image source twice when its path passes through an edge (+6 dB on that path); hybrid.early.image_sources now keeps one image per position, as ShoeBox does.
    • Fixed low-frequency bias in EDT, C50, C80, D50, DRR and Ts caused by the delay of causal octave filters.
    • Fixed speech_transmission_index returning NaN for impulse responses shorter than 1.6 s.
    • Fixed wheels that were missing the materials library, the HRTFs, the sound files and the Grasshopper components.
    • Fixed Auraliser modifying the caller's dicts, ignoring 1D responses and multichannel sounds, and wrapping energy around when resampling.
    • Fixed simulations above 16 kHz with air absorption, which failed on a 7 against 8 octave band mismatch.
    • Fixed Receiver and Source losing name, orientation, directivity and settings in JSON and copy().
    • Fixed NaN responses for a source at a receiver's position (now a ValueError), and unrelated errors for points inside a closed obstacle, scenes of obstacles only, or too few walls.
    • Fixed the hybrid failing on a fully absorbing surface, and counting a wall hit on a diffraction apex as a reflection.
    • Fixed display_in_viewer guards that treated compas.is_rhino() as a boolean, and the default HRTF path that pointed at a missing file.
    • Fixed the Grasshopper Auralise and Analyse IR components using a fixed sample rate.
    • Fixed AcousticObject.from_obj reading OBJ files in the platform's encoding: a UTF-8 byte order mark dropped the first vertex, and non-ASCII group names were garbled on Windows; files are read as UTF-8.
    • Fixed obstacle faces lying on a boundary face being counted when the scene is not aligned with the axes: the test used the distance along each axis instead of the distance to the face's plane.
